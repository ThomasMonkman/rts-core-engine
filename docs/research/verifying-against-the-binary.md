# Verifying against the real game

How to check the engine against the real Forged Alliance, and what has been confirmed so far. Behaviour still to confirm is tracked in the "Verify against the binary" issues (#7 weapons, #8 movement, #9 AI, #10 units and orders, #11 rendering and interface, #12 maths and mods). When an item is checked, tick it there and add a row to [Confirmed](#confirmed) below. New guesses go on the matching issue.

## Reference to use
- **FAF's `ForgedAlliance.exe`** (downloaded by the FAF client; DRM-free, has FAF's engine patches, loads FAF's Lua, and is the binary `../FA-Binary-Patches/include/LuaCFuncs.h` addresses refer to). The stock Steam `SupremeCommander.exe` is wrapped in Steam DRM (`.bind` section) and runs the unpatched 2007 engine, so prefer FAF's.
- CrossOver on the Mac failed because of that DRM (the bottle's Windows Steam doesn't have FA installed). On Windows, run the exe directly.

## Three ways to check
1. **Data and strings** (no game needed): `strings` on the exe, grep the game data. This is how `/lua/aipersonality.lua` (`AIPersonalityTemplate`) was found.
2. **Read the function** (no game needed): Ghidra on the exe; import names from `LuaCFuncs.h` (Lua binding -> address, e.g. `CAiPersonalityAdjustDelay` = `0x5BA970`) and struct layouts from `moho.h`, then decompile. Best for formulas and constants. Understand, then reimplement; never copy decompiled code or binaries into this repo.
3. **Differential probes** (needs the game on Windows): run the same script in the real game and in ours, and diff what each logs. How: [probing.md](../guides/probing.md).

## Static disassembly on this Mac
The retail `bin/SupremeCommander.exe` is a 32-bit PE; Xcode's
`/Library/Developer/CommandLineTools/usr/bin/llvm-objdump -d
--x86-asm-syntax=intel --start-address=0x... --stop-address=0x...` reads it
(allowed in the project's permissions). Find functions through their strings:
locate the string's address, then the code that pushes it (`68 <addr>`), then
callers by scanning for `E8 rel32` calls. FA-Binary-Patches' addresses are for
FAF's own exe and don't apply to the retail one.

| How surface units stop on a goal. Land, hover and naval units follow a path spline, one point a tick, that `CAiPathSpline::GenerateNormalSplinePoints` (MohoEngine.dll 0x101a1e80) simulates up to 20 points ahead; `CUnitMotion::CalcMoveCommon` (0x102a0360) puts the unit on the tick's point.
